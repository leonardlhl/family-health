# 安康簿 · Family Health

一個由你在本機整理、家人透過專用免登入連結查看的家庭醫療檔案。爺爺與嬷嬷分開記錄；求診、醫生、診斷、處方、覆診安排及匿名相片互相連結。繁體／簡體可切換，醫療原文保持來源寫法。

本機是主檔。GitHub Pages 只放空介面，私人資料由有專用連結驗證及讀取權限控制的雲端後端提供。家人不能修改病歷或處方；可另行填寫用藥感受。未配置雲端時，可以先使用本機功能。

## 開始使用

雙擊 `START.cmd`，會啟動本機服務並開啟瀏覽器。再次雙擊會使用同一個已運行的服務。

### 本機資料夾安排

`D:\Medical` 根目錄只保留 `爷爷医档`、`爷爷药盒`、`嬷嬷医档`、`嬷嬷药盒`、`爷爷报告`、`嬷嬷报告` 六個收件資料夾，以及 `FamilyHealth` 程式資料夾。醫檔和藥盒的原檔保持原位；報告按已核對日期與內容整理。

程式與私人主檔位於 `D:\Medical\FamilyHealth`。操作版開啟這裡的 `START.cmd` 或 `安康簿－操作版.cmd`；家人檢索預覽開啟 `VIEW.cmd` 或 `安康簿－家人檢索預覽.cmd`。版本 ZIP 放在 `FamilyHealth\releases`，不屬於網站發布內容。開發原始碼另存於 `D:\AI Projects\store app\family-health`；日常使用以 `D:\Medical\FamilyHealth` 為準。

需要 Python 3.11 或以上、Pillow 圖片處理及 PyMuPDF PDF 處理套件。本機已可執行；在另一部電腦初次設定時，可先執行 `python -m pip install -r requirements.txt`。

在這個目錄執行：

```powershell
python server.py
```

然後開啟 <http://127.0.0.1:8767>。使用這個手動命令時，伺服器運行期間保留啟動視窗；關閉後，本機介面便不能讀寫資料。`START.cmd` 則會讓服務在背景運行。不要把本機管理服務直接開放到互聯網。

可另設資料位置及端口：

```powershell
python server.py --data-dir "D:\FamilyHealthData" --port 8767
```

默認私人資料放在本專案的 `private/`。啟動畫面顯示實際收相、歸檔及備份位置，使用它們作準。

## 日常操作

1. 把新相放進 `private/inbox/grandpa/` 或 `private/inbox/grandma/`，或在本機介面上傳到相應人物。
2. 在 Codex 叫我「整理安康簿的新相」。我會掃描、讀相，把醫生、診斷、藥名、服法及覆診安排填成草稿，並列出看不清的內容。這一步由你提出要求後執行，沒有在背景自動呼叫模型。
3. 在草稿中對照來源。看不清的藥名、日期及劑量先保留待確認；歷史處方不會自動當作目前仍在服用。
4. 在相片隱私檢查中遮蓋患者識別資料，查看處理後的實際圖片，再確認紀錄。已確認資料會成為可搜尋、可備份及可發布的檔案。
5. 使用人物、日期、醫生及藥名搜尋紀錄。點開一筆求診便可查看該次處方、來源圖片及下次覆診；app 內的覆診區顯示即將到期的安排。
6. 整理完成後做備份；需要讓家人看到新內容時，再發布已確認版本。

也可在 Codex 整理時使用這些命令：

```powershell
python tools/queue.py --data-dir private
python tools/import_record.py "path\to\anonymous-draft.json" --data-dir private
```

匯入工具建立草稿，不會代替來源核對或隱私確認。欄位格式及 API 見 [CONTRACT.md](CONTRACT.md)，完整讀相流程見 [AGENTS.md](AGENTS.md)。

## 哪些資料會保存

- 人物只用「爺爺／嬷嬷」，可記錄年齡及性別。
- 保留醫生、診所、診斷、處方、覆診日期及其他與求診有關的匿名內容。
- 不保存患者真名、身份證／病人號碼、出生日期、地址或聯絡資料。這些內容也不可留在相片、條碼／QR code、附件檔名或圖片 metadata 裡。
- 未處理原相只屬本機暫存材料。正式歸檔保存的是經檢查的匿名圖片；遮蓋處理會重新編碼圖片，並清除被程式管理的未匿名來源副本。
- 你自行放入 inbox 或其他位置的原始檔，仍要留意其暫存狀態。不要把整個 `private/` 當成已匿名分享包，也不要把它加入 Git 或雲端同步目錄。

藥名和診斷以來源為準。程式負責整理紀錄，不會自動提供處方、推斷病情或改變服藥方法。

## 備份與還原

本機介面的「備份」會建立可還原的 ZIP，包括**已確認紀錄及已通過隱私檢查的歸檔圖片及 PDF**。備份刻意排除未確認草稿、未檢查相片及原始 inbox；介面會顯示排除數量。仍有待處理項目時，先完成整理，才有完整的正式檔案備份。

把產生的 ZIP 另存 USB 或外置硬碟，可以在電腦或硬碟損壞時保留一份。只把副本放在同一硬碟，不能應付該硬碟損壞。備份含醫療資料，應保存在你控制的位置；不能當作公開下載檔案。

還原先上傳備份查看預覽，核對紀錄／圖片數量後再套用。程式會先備份目前可備份的正式檔案，再還原；本機尚未確認的草稿及待處理附件會保留。這些待處理項目仍不在備份 ZIP 內，搬到另一部電腦前應先完成整理。

## 家人免登入查閱及發布

部署步驟、雲端權限及管理密鑰設定見 [CLOUD-SETUP.md](CLOUD-SETUP.md)。必須完成私人資料表／相片權限設定及分享服務部署，才建立專用連結。

在本機操作版開啟任一人物 →「設定」→「家人免登入連結」。建立後複製完整連結傳給家人；家人開啟後只見爺爺／嬷嬷的就診、藥物及報告。可重設連結使舊連結失效，或停止分享。持有連結的人都能查閱，請只傳給家人。撤銷可阻止之後的讀取，但不能收回已下載或截圖的內容。

分享連結的明文只保存在本機 `private/family-share.json`，雲端只保存雜湊；不包含在 Git、網站建置或病歷備份內。原有帳戶登入保留為另一條查閱途徑，停止分享不會停用帳戶權限。

```powershell
python tools/build_site.py --require-cloud
python tools/publish.py --data-dir private --dry-run
python tools/publish.py --data-dir private
```

`build_site.py` 建立網站空介面；`publish.py` 發布已確認匿名紀錄及相片。發布先完成新版本，再切換家人看到的版本；家人頁面顯示最後發布時間。沒有重新發布，本機修改不會自動出現在家人的網站。

網站可以在你的電腦關機時顯示最後成功發布的版本。提醒只在 app 內顯示，家人需要打開 app 才看到；沒有手機推播、手機日曆同步或持續背景提示。

## 此電腦的交付位置

開啟 `D:\Medical\FamilyHealth\START.cmd`。程式只在本機 127.0.0.1:8767 提供管理介面。醫療資料在正式安裝的 private 資料夾；GitHub 與交付 ZIP 不含病歷。已設定讀取 D:\Medical 下六個爺爺／嬷嬷醫檔、藥盒及報告資料夾；檢查新相會保留來源檔案。尚未完成身份資料檢查的相片不會自動顯示縮圖，須進入相片檢查。


## 操作版與家人檢索版（1.1）

- `START.cmd`：你的操作版，整理相片、草稿、診斷、處方及備份。
- `VIEW.cmd`：本機預覽家人檢索版，只讀已確認及已完成身份檢查的內容。這是本機預覽入口，不是獨立使用者登入或發布。
- 家人網站只提供檢索版，可使用已設定的專用免登入連結或獲准帳戶。
- 兩版都先選爺爺／嬷嬷章節，再看該人物的紀錄。沒有合併人物的按鈕。
- 藥物可連結自己的相片；沒有指定時，明確顯示本次求診來源相片。列表讀取 960 px / JPEG 86 壓縮預覽，點開保留清晰原圖。未檢查相片不自動顯示。

檢索版進入人物章節後只顯示「求診紀錄」與「藥物紀錄」，預設開啟求診；覆診管理、草稿、匯入及備份只在操作版。藥物按求診日期由新至舊分組，桌面左側／手機列表上方可篩選藥物種類。種類由操作版核對填寫，未確定維持未分類。


## 報告、檔名與 PDF

把報告放進 `D:\Medical\爷爷报告` 或 `D:\Medical\嬷嬷报告`，支援 JPG、PNG、WebP 和 PDF；報告資料夾會連同子資料夾掃描。建議每份報告使用 `YYYY-MM-DD_簡要內容` 子資料夾，例如 `2026-10-20_驗血報告` 或 `2026-10-20_Blood-test`。日期不明時先保持待確認，不能用檔案修改時間代替報告日期。

本機選人物 → 文件 → 檢查新檔；Codex 逐頁閱讀後可在「報告」建立草稿。每份報告保留日期、簡要內容、種類、醫院／化驗所、醫生和摘要，並連結全部來源。確認後安全檔案放進 `private/archive/reports/<人物>/<日期>_<簡要內容>/`，例如 `2026-10-20_爺爺_驗血報告_01.pdf`。碰到同名時加唯一後綴，內部附件 ID 不變。原始收件檔案的整理改名只在已核對來源及安全歸檔成功後進行；不把未遮名原件當作雲端檔案。

PDF 每份上限 50 MB、80 頁，另設像素安全限制；過大文件先按報告拆分。操作版逐頁框選姓名、病歷號碼、條碼等身份資料，每一頁都須核對。儲存時以 180 dpi、長邊最多 3000 px 重新建立影像 PDF，移除隱藏文字、metadata、表單、註記及附件；JPEG 內容以品質 90 壓縮。仍須打開實際處理結果確認小字清晰。安全縮圖另外壓縮，家人先看縮圖，需要時才開啟完整文件。PDF 不保留原本可搜尋的文字層，檢索依靠已核對的標題、日期、醫生及摘要。

同一份來源只需完成一次有效核對；內容改動會撤銷相關確認。備份、還原、發布包含已確認報告及安全 PDF。沒有新報告時維持空清單，不會加入示範病歷。

## 容量與網址

操作版「設定 → 儲存空間」顯示雲端文件、資料庫和本機安全檔案／備份用量。容量參考 Supabase 免費方案：1 GB 文件、500 MB 資料庫；這不是讀取帳戶帳單的結果，實際配額以帳戶為準。每月傳輸量另計，介面目前不計算流量。接近參考容量 80% 時提示。

同步以內容雜湊識別檔案。相同內容在不同版本共用同一份已驗證物件；完全未變更的已確認版本會核對雲端後跳過重複發布。舊版檔案及發布歷史仍計入用量，不自動刪除。先壓縮、定期觀察用量；需要時再安排可審核的舊版本清理或升級方案。備份留在本機，並自行另存外置硬碟。

GitHub Pages 放程式介面，醫療資料放 Supabase，所以網址並不代表資料全部存在 GitHub。`#share=` 後面是免登入連結的私密鑰匙，不能直接刪掉或縮成易猜的代碼。自訂域名只能縮短網站前半部分，需另外持有域名並更新部署設定；本版沒有購買域名或使用第三方短網址。


## 家人記錄用藥感受

家人網站 → 選爺爺／嬷嬷 → 藥物 →「記錄感受」。選「有效／無效／待定」，可以加最多500字備註，再按「儲存感受」。儲存成功後其他家人重新載入即可看到；每次修改均保留歷史。未填寫會清楚標示，並非默認已填待定。

感受只代表家人的觀察，與醫生處方分開；不會自動改動服法或是否仍在服藥。備註不要填姓名、證件或聯絡資料。共用連結只顯示「家人填寫」與時間，不能辨認實際是哪個人。

同時修改會顯示最新內容，保留你正在填的草稿，再由你決定採用哪份。儲存時斷線，按「重試儲存」可核對同一筆結果，不會重複新增。藥物主檔更新時要重新核對再填。

本機操作版重新載入資料，會拉取並保存感受；備份前亦會同步。離線時可以備份已有內容，但會提示尚未取得最新感受。還原舊備份不會刪走較新的本機感受，也不會覆蓋雲端。網站對病歷仍無編輯權限，本機家人預覽及示範頁不提供雲端感受寫入。
